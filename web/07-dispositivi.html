7 · Sui dispositivi reali

Lo stesso programma del simulatore gira su Puck.js ed ESP32 con Espruino, e i dispositivi si parlano via Bluetooth Low Energy.

Cosa va sul dispositivo

  • nbrjs (src/core.js): il core, circa 5 KB;
  • nbrjs/ble (src/ble.js): il trasporto. Ogni round il messaggio finisce nel pacchetto di advertising BLE, e i vicini sono i dispositivi sentiti negli ultimi secondi. Nessuna connessione, nessun pairing.

Il simulatore e questo sito non vanno sul dispositivo.

Il limite: 23 byte

Un pacchetto di advertising contiene circa 23 byte utili. Qui sotto c'è il gradiente in salti che gira sui dispositivi: passa sopra un nodo per vedere i byte del messaggio.

Sono circa 10 byte: ci stanno. Qualche regola per restare sotto il limite:

  • preferisci interi a decimali (1.4142135 occupa 9 byte);
  • pochi operatori aggregati per programma: ognuno aggiunge una chiave (x0, x1...);
  • i messaggi per-vicino di xc costano circa 10 byte per vicino: con BLE sono adatti a pochi vicini;
  • se il messaggio non ci sta, il dispositivo lo scrive in console e non lo trasmette.

Come distanza dai vicini, sui dispositivi c'è nbrSense('rssi'): la potenza del segnale ricevuto, in dBm (più vicino a 0 vuol dire più vicino).

Simulazione o rete reale: cambia solo la config

Il programma aggregato non sa dove gira. Lo decide start(program, config), in base a config.target:

  • 'sim': il simulatore (qui nel browser o in Node), con nodes, layout, range;
  • 'ble': Puck.js ed ESP32, con period e ttl (dopo quanti secondi un vicino muto viene dimenticato).

I campi comuni sono period, sensors(id) (i valori letti con sense()) e onResult(valore, id). Nel playground è la scheda config.js. Ecco il file completo per i dispositivi, examples/hops.js:

// Hop-count gradient on Puck.js or ESP32 (Espruino), over BLE.
// Press the button to toggle the source; LEDs show the hops: 0 red, 1 green, 2 blue, more off.
// Bundle and upload: npm run bundle -- examples/hops.js > dist/hops.js
require('nbrjs').globals();

// The aggregate program: identical in the simulator and on the devices.
var hops = (src) => share(Infinity, (d) => src ? 0 : d.min() + 1);
var program = () => hops(sense('source'));

// Puck.js pins. ESP32 dev boards: e.g. BUTTON = D0 (BOOT), LEDS = [D2].
var BUTTON = BTN, LEDS = [LED1, LED2, LED3];
var source = false;
setWatch(() => { source = !source; }, BUTTON, { edge: 'rising', repeat: true, debounce: 50 });

// Only the config knows where the program runs: target 'ble' here, 'sim' in the simulator.
start(program, {
  target: 'ble',
  period: 1000,
  sensors: () => ({ source: source }),
  onResult: (h, id) => {
    LEDS.forEach((l, i) => l.write(i === h));
    console.log(id + ' hops=' + h);
  }
});

Caricarlo

Tre strade, dalla più rapida:

  1. Dal playground: il pulsante Espruino ↗ genera il file pronto, con i moduli dentro e target: 'ble'. Copialo nell'Espruino Web IDE (editor a destra), connettiti al dispositivo e premi Upload.
  2. Dal Web IDE, con i moduli online: in Settings → Communications → Module URL aggiungi, separato da |, l'indirizzo …/modules di questo sito. Poi require('nbrjs') e require('nbrjs/ble') funzionano come i moduli ufficiali. Con questa strada scrivi esplicitamente require('nbrjs/ble'), perché l'IDE carica solo i moduli che vede nominati.
  3. Da riga di comando: npm run bundle -- examples/hops.js > dist/hops.js crea lo stesso file del pulsante.

Ripeti su almeno tre dispositivi e premi il pulsante su uno: i LED mostrano i salti (rosso 0, verde 1, blu 2). Il codice caricato senza save() resta in RAM: per ripartire basta togliere la batteria.

Su ESP32 il BLE dev'essere attivo nel firmware (ESP32.enableBLE(true), poi riavvio). ESP-NOW non è esposto da Espruino, quindi Puck.js ed ESP32 si parlano via BLE.

Le regole di Espruino

Il codice è interpretato direttamente dal sorgente, con un sottoinsieme di JavaScript:

  • sì: arrow function, template literal, classi, Math, JSON, metodi degli array;
  • no: destructuring, spread, parametri di default, Map/Set, for...of, async;
  • niente hoisting: definisci le funzioni prima di usarle (var f = () => ...).

Il playground usa lo stesso stile, quindi quello che scrivi qui funziona anche lì.
