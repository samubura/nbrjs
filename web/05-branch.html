5 · Alignment and branches

Devices only exchange values computed by the same piece of the program. Around an if, this needs care, and NbrJS takes care of it.

Alignment

Every aggregate operator gets a name from its position in the program: the first is x0, the second x1, and so on. Two devices exchange values only under the same name: they are aligned. This is what lets you compose blocks without them interfering.

What NbrJS does

Before running your program, the playground and the device upload rewrite every if, ?:, && and || that wraps aggregate code into a branch. The same program as above, with alignment on, as everywhere else on this site:

Now nodes 2 and 5 show 1. branch(condition, () => ..., () => ...) runs one side and puts the condition in the name: the operators become b0.1/x0 and b0.0/x0. Devices that took different sides are no longer aligned, and the network splits into two separate domains. Hover a node to see the names in its message.

Named functions get the same treatment: two different functions never share messages, even when one variable holds either of them.

The rewrite happens in the tools: the playground, its device upload and scripts/bundle.js. Code typed straight into the Espruino console is not rewritten: there, write branch(...) yourself around aggregate code.

A gradient that goes around obstacles

With a branch, obstacles leave the computation, and the gradient flows around them.

Try it

1. Two separate worlds: nodes with x < 3 compute the gradient, the others count their neighbours.

2. Write the obstacle gradient with an explicit branch, as you would in the Espruino console.

Solutions 
var program = () => sense('x') < 3 ? distanceTo(sense('source')) : neighbourCount();

var program = () => branch(sense('obstacle'), () => null, () => distanceTo(sense('source')));
